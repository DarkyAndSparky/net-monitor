Docs / Установка

Установка

Ручная установка на Windows или Linux/macOS без Docker.

Windows (install.bat)

Запустите install.bat от имени Администратора — скрипт сам установит зависимости, скомпилирует better-sqlite3 и сгенерирует TLS-сертификат.

install.bat        # от имени Администратора!
⚠ better-sqlite3 — нативный модуль, требует компиляции. Скрипт установит windows-build-tools и node-gyp автоматически. Если автоустановка не прошла — установите Visual Studio Build Tools вручную, затем запустите npm rebuild better-sqlite3.

Ручной запуск (если скрипт не устраивает)

npm install
node server.js

Linux / macOS (install.sh)

chmod +x install.sh
./install.sh

Скрипт определяет пакетный менеджер (apt / yum / brew) и устанавливает build-зависимости (python3 make g++) автоматически.

Первый запуск

При первом старте автоматически создаётся:

ЧтоГдеПримечание

Пользовательadmin / admin⚠ Смените пароль после первого входа

TLS-сертификатdata/certs/Самоподписанный, генерируется make-cert.bat/.sh
✓ Сервер запущен: откройте https://localhost:9222. Браузер покажет предупреждение о самоподписанном сертификате — нажмите «Дополнительно» → «Перейти на сайт».

Docs / Docker-деплой

Docker-деплой

Рекомендуемый способ для продакшн-серверов на Linux.

Быстрый старт

git clone https://github.com/DarkyAndSparky/net-monitor.git
cd net-monitor
docker compose up -d

Сервис поднимается на порту 9222. Данные хранятся в ./data (volume).

network_mode: host — используется чтобы контейнер мог пинговать устройства локальной сети. На Windows Docker Desktop это не работает — Docker-образ предназначен для деплоя на Linux-сервер.

docker-compose.yml

services:
  net-monitor:
    build: .
    container_name: net-monitor
    restart: unless-stopped
    ports:
      - "9222:9222"
    volumes:
      - ./data:/app/data
    network_mode: host   # нужен для ping в локальной сети
    cap_add:
      - NET_RAW          # разрешает ping
      - NET_ADMIN        # разрешает ARP

Сборка образа

docker build -t net-monitor .
docker run -d --name net-monitor --network host   -v $(pwd)/data:/app/data   --cap-add NET_RAW --cap-add NET_ADMIN   net-monitor

Обновление

git pull
docker compose build --no-cache
docker compose up -d
Данные сохраняются — volume ./data не пересоздаётся при обновлении контейнера.

Переменные окружения в Docker

environment:
  - PORT=9222
  - METRICS_TOKEN=мой_секрет
  - HTTP_REDIRECT_PORT=0   # отключить редирект если не нужен
Docs / Настройка

Настройка системы

Все настройки хранятся в SQLite таблице settings и меняются через UI или API.

Фиче-флаги

Раздел Настройки → Функции. Все дополнительные модули выключены по умолчанию.

ФлагЧто включает
snmpSNMP-опрос устройств (OID, аптайм, CPU MikroTik)
portChecksПроверка TCP-портов сервисов
incidentsЖурнал инцидентов + эскалация алертов
auditLogАудит-лог всех действий пользователей

Интервалы мониторинга

Глобальный интервал по умолчанию — 60 сек. Минимальный интервал — 10 сек. Задаётся индивидуально для каждого устройства в его карточке → поле «Интервал проверки».

⚠ При большом числе устройств (N) и малом интервале (I) у сервера будет N/I одновременных ping-запросов. Для 500 устройств с интервалом 30 сек — ~17 пингов в секунду. Планировщик запускает новый тик каждые 5 сек и конкурентно не перегружает сеть, но учитывайте нагрузку на систему.

TLS / HTTPS

Если файлы data/certs/cert.pem и data/certs/key.pem существуют — сервер автоматически запускается по HTTPS. Для генерации самоподписанного сертификата:

make-cert.bat    # Windows
bash make-cert.sh  # Linux/macOS

Для использования своего сертификата (Let's Encrypt и т.д.) — укажите пути через переменные окружения TLS_CERT_FILE и TLS_KEY_FILE.

Docs / Бэкап и восстановление

Бэкап и восстановление

Через UI

Настройки → Резервная копия → кнопка «Скачать бэкап». Скачивается JSON-файл с полным дампом: устройства, категории, топология, настройки, инциденты, аудит (последние 5000 записей).

⚠ Восстановление полностью заменяет текущие данные. Перед восстановлением рекомендуется сохранить текущий бэкап.

Через API

# Скачать бэкап
curl -s -b cookies.txt https://localhost:9222/api/backup -o backup.json

# Восстановить
curl -s -b cookies.txt -X POST https://localhost:9222/api/backup/restore \
  -H "Content-Type: application/json" --data @backup.json

Прямой бэкап SQLite

Файл data/netmonitor.db — обычный SQLite. Можно копировать напрямую (сервер должен быть остановлен, или использовать sqlite3 .backup).

# Горячая копия (сервер может работать)
sqlite3 data/netmonitor.db ".backup data/netmonitor-backup.db"

Структура JSON-бэкапа

{
  "version": 2,
  "exportedAt": "2026-08-08T...",
  "devices": { "devices": [...], "categories": [...] },
  "users": { "users": [...] },
  "settings": { "mikrotiks": [], "alerting": {}, "features": {}, ... },
  "topology": { "edges": [...] },
  "incidents": { "closed": [...] },
  "audit": { "entries": [...] }
}

Docs / Интеграции

Интеграции

MikroTik RouterOS API

Настройки → Интеграции → MikroTik. Добавьте роутер (хост, порт 8728, логин/пароль). Доступные операции:

ОперацияЧто делает
Импорт DHCP-leasesТянет список аренд DHCP, добавляет новые устройства, обновляет IP/MAC существующих
ARP-таблицаСписок устройств из ARP-таблицы роутера с указанием интерфейса
MNDP-соседиОбнаружение MikroTik-устройств через neighbor discovery
АвтотопологияСтроит связи на карте из neighbor-таблицы + ARP (вкладка Обнаружение)
Для подключения по TLS укажите порт 8729 и включите галочку «Использовать TLS».

UniFi Controller

Поддерживаются UniFi Network Application и UniFi OS (UDM/UDR). При добавлении включите галочку «UniFi OS» для современных устройств. Импортирует инфраструктуру (UAP, USW, UGW) и клиентов.

Самоподписанный сертификат UniFi — соединение устанавливается с отключённой проверкой сертификата (rejectUnauthorized: false). Используйте только в доверенной сети.

Cisco SSH

Подключается по SSH, выполняет show ip arp и парсит ARP-таблицу. Поддерживаются старые алгоритмы шифрования (IOS 12.x+). Импортированные устройства получают категорию «workstation», тип «DHCP Client».

OUI (производители по MAC)

База производителей скачивается с standards-oui.ieee.org при первом запуске и обновляется раз в 30 дней. Раздел Настройки → OUI → «Обновить сейчас» для принудительного обновления.

Docs / Алерты и уведомления

Алерты и уведомления

Настройка

Настройки → Алерты. Включите «Алерты активны» и настройте хотя бы один канал доставки.

Telegram Bot

# 1. Создайте бота через @BotFather, получите токен
# 2. Узнайте chat_id: отправьте боту любое сообщение, затем:
curl https://api.telegram.org/bot<TOKEN>/getUpdates
# В ответе найдите "chat":{"id": ...}

Введите токен и chat_id в настройках. Кнопка «Тест» отправит пробное сообщение.

Webhook

POST-запрос на указанный URL с JSON-телом:

{
  "device": { "id": "d-...", "name": "router-01", "ip": "192.168.1.1", "location": "Серверная" },
  "status": "down",          // "down" | "up" | "test"
  "message": "🔴 router-01 недоступно\nIP: 192.168.1.1",
  "time": "2026-08-08T10:00:00.000Z"
}

Параметры алертов

ПараметрОписание
Порог срабатыванияСколько подряд неудачных проверок до отправки алерта (по умолчанию 2)
Повтор (мин)Повторять алерт пока устройство offline. 0 — только один раз
Уведомить о восстановленииОтправить сообщение когда устройство снова онлайн

Эскалация (требует модуль «Инциденты»)

Если устройство недоступно дольше N минут — отправляет отдельное сообщение на другой Telegram chat_id (например, дежурному руководителю). Инцидент помечается флагом «escalated».

Алерты на устройство

В карточке каждого устройства есть галочка «Алерты». Снимите её чтобы исключить конкретное устройство из системы уведомлений, оставив его под мониторингом.

Docs / SSE / Реалтайм

Server-Sent Events

Живые обновления статусов без перезагрузки страницы.

Эндпоинт

GET /api/events
Authorization: сессионный cookie (требует входа)

Как работает

После логина браузер подключается к /api/events через нативный EventSource. Сервер держит соединение открытым и пушит события при изменении данных. При разрыве — автоматическое переподключение через 5 сек.

События

eventКогдаdata
snapshotСразу при подключенииМассив текущих статусов: [{"id":"d-...","online":true,"lastChecked":...}]
statusПри смене online↔offline{"id":"d-...","online":false,"lastChecked":1234...}
incidentОткрытие/закрытие инцидента{"type":"open","deviceId":"...","deviceName":"..."}
pingКаждые 25 сек{"ts":1234...} — keepalive

Реакция фронтенда

СобытиеЧто обновляется
snapshotПолная перерисовка дашборда, таблиц, карты
statusТолько кольцо нужного узла на SVG-карте + строка в таблице мониторинга + счётчики дашборда
incidentToast-уведомление в браузере

Защита от перегрузки

SSE генерирует событие только при смене статуса (prev.online !== online), а не при каждом тике планировщика. При N устройствах с интервалом T — максимум N/T событий в секунду, обычно значительно меньше.

Prometheus /metrics

Эндпоинт

GET /metrics
Content-Type: text/plain; version=0.0.4

Формат: Prometheus text exposition v0.0.4. Без авторизации по умолчанию. Для защиты — переменная окружения METRICS_TOKEN.

Разработка и контрибьюшн

Локальный запуск

git clone https://github.com/DarkyAndSparky/net-monitor.git
cd net-monitor
git checkout dev        # вся работа в ветке dev
npm install
node server.js          # http://localhost:9222

Ветки

ВеткаНазначение
mainСтабильные релизы. Прямые коммиты запрещены — только merge из dev через PR.
devТекущая разработка. Все изменения сюда.

Выпуск новой версии

git checkout main
git merge dev
git push
git tag v1.0.0
git push origin v1.0.0   # GitHub Actions автоматически создаст Release с zip

POST/api/login Вход в систему

Body

{ "username": "admin", "password": "admin" }

Response 200

{ "ok": true, "username": "admin", "role": "admin" }

Response 401

{ "error": "invalid_credentials" }

Response 429

{ "error": "too_many_attempts", "message": "Повторите через ~5 мин." }

После 5 неудачных попыток с одного IP — блокировка на 5 минут.

POST/api/logout Завершение сессии

Response 200

{ "ok": true }

Body

Минимальная длина нового пароля — 8 символов.
